# 语音输出 · 本地开发测试

语音输出已随 v0.1.24 发布到 Windows 和 macOS。本文保留独立开发入口与配置、测试说明。

运行 `npm run dev:voice`，打开标题带“语音开发版”的窗口。它使用项目下 `work/voice-dev-profile` 保存独立配置与测试数据，不替换现有开发版或安装版的数据。窗口会自动打开“设置 → 语音输出”。

1. 填写**火山引擎语音服务的 API Key**，与聊天模型的 Key 分开。新版控制台的语音 Key 使用 `X-Api-Key` 鉴权；不要把旧版 Access Token 或方舟聊天 Key 直接填入。
2. 分别为知序和枫言选择音色，也可选择“自定义音色 ID”并粘贴控制台中的 ID。
3. 点击语音区域的“测试语音并试听”或人物音色下的“试听”，可测试尚未保存的语音配置；测试期间可以“停止播放”。试听会调用语音服务。
4. 勾选“开启语音输出”，按需要保留“自动语音输出（新回复与提醒）”，保存设置。默认未开启，不会自动发送语音请求。
5. 新回复和主动提醒会按顺序朗读；点击发送者名字旁的声音图标可手动重播，生成或播放时图标变为停止，再次点击即可取消。自动朗读关闭后仍可手动播放；关闭语音输出则不调用服务。

大模型区域单独提供“测试大模型”，只使用该区域尚未保存的接口地址、Key 和模型名称，以最小请求检查连通性和工具调用；不执行完整 Agent、不读取任务和聊天，也不保存配置。普通聊天可连接但工具调用未确认时会明确提示，不误报为 Key 无效。大模型与语音请求均使用 Electron 网络层，跟随系统代理。设置底部仅保留“保存设置”，不再提供总测试按钮。

连接测试正常只发一次请求，不自动重试 503／429；仅遇到 400／422 时多发一次不带工具的兼容探测。服务端对完整流程（含响应正文）设置 20 秒硬超时；界面显示等待秒数、支持取消，并另设 25 秒兜底，成功后显示实际耗时和请求次数。修改配置、关闭设置或开始聊天会取消旧测试。设置打开时不启动新后台模型检查；已有对话、后台检查或瞬笺生成尚未结束时，测试提示稍候，避免额外并发。

聊天遇到 503 等临时 HTTP 故障或 429 限流时，重试仍最多两次，分别等待至少 2 秒和 4 秒并加少量随机间隔，遵守服务商的 Retry-After。服务商要求等待超过 30 秒时结束本轮，让用户稍后重发；不在冷却期内抢发。认证、余额、权限和参数等明确的永久错误不重复调用。状态变化保护与成功后一次提交不变，失败不保存草稿。503 显示服务繁忙，429 显示限流，不再统一引导用户检查 Key。

关于 DeepSeek：官方将 [503 定义为服务器繁忙、429 定义为速率或并发超限](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)，并说明 [等待推理时可能用空行保持请求连接](https://api-docs.deepseek.com/quick_start/rate_limit/)。一次 503 无法证明账号触发了 QPS 上限；此前没有保存那次慢请求的耗时，不能从错误文本还原具体等待阶段。

默认是豆包语音合成 2.0：

- 接口：`https://openspeech.bytedance.com/api/v3/tts/unidirectional`
- 模型资源 ID：`seed-tts-2.0`
- 知序默认：灵动欣欣 2.0，`ICL_uranus_zh_female_lingdongxinxin_tob`；备选：`zh_female_qinqienv_uranus_bigtts`、`zh_female_jiaochuannv_uranus_bigtts`、`zh_female_shuangkuaisisi_uranus_bigtts`。
- 枫言默认：小天，`zh_male_taocheng_uranus_bigtts`；备选：`zh_male_ruyayichen_uranus_bigtts`、`zh_male_kailangxuezhang_uranus_bigtts`。

知序下拉列表提供一个默认与三个备选，枫言提供一个默认与两个备选，并保留自定义入口。旧默认亲切女声／儒雅逸辰自动迁移至新默认；配置记录默认版本，之后主动选回备选会保留，其他有效备选和自定义 ID 也保留。

“你能说话吗”会根据实际配置说明语音能力；聊天模型也会获得不含密钥的开关状态，不再沿用旧的“语音我发不了”说法。关闭自动语音输出后，普通回复与提醒不会自动播放，但消息旁的手动朗读仍然有效。

高级配置可填写接口地址、资源 ID 和可选模型版本。音色必须属于所选模型资源，复刻音色还需相应服务权限。接口自定义仅支持豆包语音协议，不使用聊天模型的 chat/completions 地址。

仅将需要朗读的文字发送给配置的语音服务。Key 只保存在本机，不发送给聊天模型，也不进入导出备份；导入备份不接受备份里的 Key，仅在接口相同时保留本机已有语音 Key。音频在内存中播放，不写入备份或对话内容；文字聊天和任务保存不等待语音合成。

长回复会清理 Markdown、链接地址与代码块，并分段合成、依次播放。播放前先完整解码，并在每段前加入 1 秒静音，让设备先完成启动及约半秒的音量渐强，等待播放器缓冲就绪后从零开始播放，减少音频设备启动时吞掉首字的问题；保留全部原始语音采样，不通过删除或淡入语音内容处理。对应弹窗已安排自动朗读时不同时播放提示音，避免掩盖开头。切换人物、发送下一条消息、清空聊天、修改语音配置或点击停止时，取消当前生成与待播队列。语音服务失败只显示语音提示，文字回复与任务不回滚。

测试命令：

```powershell
npm run check
npm test
npm run test:speech-ui
npm run test:model-settings
```

界面测试使用独立临时数据、本机模拟模型和豆包响应及有效音频样本，验证两类测试的 Key 隔离、草稿不保存、取消旧测试、新默认音色、声音／停止图标，以及真实播放器、自动朗读、提醒、失败回退与人物切换；它不需要真实 Key，不产生豆包调用费用。真正的音色、账号权限与服务可用性，需要用户在开发版中填写自己的 Key 后试听。

接口实现依据：[豆包 HTTP 单向流式语音合成](https://docs.volcengine.com/docs/doubao-voice/http-chunked-sse-unidirectional-streaming-v3?lang=zh)、[豆包语音合成 2.0 音色列表](https://docs.volcengine.com/docs/doubao-voice/tone-list-3?lang=zh)。
